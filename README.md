# Wordkeep

英単語の間隔反復（SRS）学習PWA。単体HTMLファイル（`index.html`）で動作します。v4.3.0からログインが必須で、単語はアカウント（Firestore）に自動同期され、端末側の localStorage はその手元のコピーとして動きます。

姉妹アプリだった `idiomkeep.html`（熟語版）は提供終了しました（履歴からは復元可能）。

## 機能

- 単語の追加・検索・編集・削除（重複追加は防止）
- フラッシュカード（暗記用、復習スケジュールには影響しません）
- 4択 / 入力式クイズ。4択の誤答はスペル/意味が似たものを優先的に選出（レーベンシュタイン距離の重み付きサンプリング）
- 間隔反復スケジュール（正解で 1→3→5→7→14→20→30→60→90日後に再出題、不正解で最初からやり直し）。一時期「不正解でも1段階戻るだけ」に緩めたが、90日→60日では間隔が長すぎて学習にならないため元の厳しさに戻した
- 辞書API（dictionaryapi.dev）＋翻訳API（MyMemory）による単語検索（ログイン不要）。英英辞書の定義も対象言語に翻訳して表示
- 入力中にDatamuse API（無料・キー不要）でオートコンプリート候補を追加表示。
  辞書に見つからない語には「もしかして」でスペル修正候補（定義付き）を提案
- 多言語対応：日本語 / English / 中文 / Français / العربية / 한국어 / Русский（UI表示と訳の言語を設定で切替、アラビア語はRTL対応）
- 学習の記録画面（下部タブの「記録」、またはヘッダーの🔥バッジから）。現在／最長の連続日数、学習した日数、通算正答率のタイル、直近14日の復習数の棒グラフ、半年分（26週）のGitHub風コントリビューションカレンダー（4段階の濃淡・セルにツールチップ）。集計元は各単語の`hist`（クイズの解答のみ。フラッシュカードはSRSに影響しない設計のため含まない）で、自分の単語帳（`wordkeep.v2`）とパッケージ（`wordkeep.packages.v1`）の両方を合算。日付の集計は既存のSRSと同じローカル暦日基準。`hist`は1単語あたり50件までなので、極端に復習の多い単語は古い分が切り捨てられる
- 単語の発音再生に対応（Web Speech API／オフライン・APIキー不要）。リスト・単語帳の表裏・クイズ・検索結果の🔊ボタンで再生。設定 > 発音 で自動再生のオン／オフ、アクセント（米／英）、速さ（ふつう／ゆっくり）を選択可。クイズは「意味→単語」出題のときだけ再生を出さない（答えの読み上げになるため）。macOSはネタ音声（Albert等）が一覧の先頭に並び、`default`音声はOSのUI言語（日本語）になるため、標準音声名（Samantha/Daniel/Google US English等）を優先して選択。非対応ブラウザでは発音セクションごと非表示
- ライト／ダークテーマ対応（設定 > 表示）。「自動（端末の設定に追従）／ライト／ダーク」を選択でき、基本の紺＋ゴールドはそのままに白い面を落ち着いたダークグレーへ切替。全色をCSS変数化し`:root[data-theme="dark"]`で上書き。自動時は`prefers-color-scheme`に追従（フォーカス／可視化時に再判定するフォールバックあり）、`<meta name="theme-color">`も同期
- テーマ別の単語パッケージ：あらかじめ用意した配布デッキを、リスト/単語帳/復習の各画面上部の単語帳セレクターから切り替えて学習。パッケージごとにコンプリート率（%）を表示し、進捗は自分の単語帳（`wordkeep.v2`）とは別キー（`wordkeep.packages.v1`、パッケージID＋英単語で一意）で完全に分離管理。収録は「語学留学の英単語 Part1 / Part2 / Part3」（各50語）。タイトル・単語の意味とも対応7言語すべてに翻訳済みで、表示言語に合わせて自動切替。リスト検索は単語・意味（全7言語）に部分一致
- リスト画面の先頭に「今日」のカード（プッシュ通知が使えない構成のため、開いた瞬間に復習へ誘導する代替）。状態に応じて4通り: 未着手×要復習（連続記録が途切れる旨を明示）／今日学習済み×残りあり／要復習なし×連続中（自由学習へ誘導）／今日完了。要復習も連続記録もない場合は表示しない。ブラウザのタブのタイトルにも残り語数を表示
- 画面構成：下部タブは リスト / 単語帳 / ＋ / 復習 / 記録。設定はヘッダー右上のメニュー（三本線）からモーダルで開く
- 初回起動時のチュートリアル（お試し単語5つを自動追加）、アップデート後の「更新のお知らせ」、設定 > ヘルプ下に全リリースの更新履歴
- インストール可能なPWA（`manifest.json` ＋ `service-worker.js`）。Android/Chromeではブラウザからホーム画面追加（インストール）を促され、追加後はオフラインでも開けます。`icon-192.png` / `icon-512.png` は暫定プレースホルダ（濃紺角丸＋「W」）で、正方形のロゴが用意でき次第そのまま差し替え可能
- ダブルタップでのズームを無効化（`touch-action:manipulation`）
- JSONバックアップの書き出し・読み込み

## 使い方

`index.html` をそのまま開くか、GitHub Pages などで公開するだけで動作します。ビルド手順は不要です。

## 効果音について

クイズの回答時に短い音を鳴らします（設定 → 効果音 でオフ可、既定はオン）。

- **音源ファイルを持たず Web Audio API で生成**している。単一HTML構成を崩さず、読み込みも増えず、初回からオフラインで鳴る
- 正解は上がる長三度（G5→C6）、不正解は低く短い2音。**ブザーにはしていない**：学習アプリで毎回不快な音が鳴るのは、学習をやめる理由になる
- オシレータは瞬間的にオン／オフすると可聴なクリックが出るため、短いアタック／ディケイのエンベロープをかけている
- ブラウザの自動再生ポリシーで `AudioContext` は操作があるまで suspended になる。回答クリック自体が操作なので、初回再生時に `resume()` する
- 読み上げ（TTS）と重なると双方聞き取りにくいので、効果音がオンのときは発音を約340ms遅らせる。**先に「次の問題」を押した場合はタイマーを破棄する**（さもないと次の問題の上に前の単語が読み上げられる）

## 単語詳細について

- **類義語**: 辞書API（dictionaryapi.dev）のレスポンスに品詞ごとの`synonyms`が含まれているため、それを保存・表示（最大6件、最大3品詞ぶん）。追加の通信は発生しない
- **品詞ラベル**: `POS_LABEL`で英語の生の品詞タグ（noun/verb/adjective等）を7言語の短い表記に変換してリストに常時表示
- **単語タップで詳細ポップアップ**: `wordDetailHTML(w)`をフラッシュカード裏面（`renderBack`）と共有し、内容が食い違わないようにしている
- **メモ欄（`note`）**: 単語追加時・リストの編集フォームの両方から自由記述できる（例文・覚え方など）。既存の単語オブジェクトに1フィールド足しただけなので、クラウド同期・検索・詳細ポップアップに自然に乗る。リストには📝アイコンで存在だけ示し、内容は詳細ポップアップで見る


## Firestoreルールのテスト

`tests/` にエミュレータで動かす検証スクリプトがあります（31件）。ルールは読んで正しそうに見えても動かないことがあるため、**コンソールに貼る前に必ず通してください**。手順は `tests/README.md`。

実際にこれで見つかった不具合が2件あります。

- `match /{document=**}` は rules_version 2 では**0個以上**のパスに一致するため、親ドキュメント `users/{uid}` にも無条件の `write` を与えていた。ルールの権限はOR結合されるので、この1行が**ニックネームの7日制限を完全に無効化していた**（何度でも即時に改名できる状態だった）。サブコレクションは明示的に列挙する形に変更
- `allow write` は削除も含むが、削除時 `request.resource` は null。`.data` を読むと例外になり、例外は拒否として扱われるため、**本人が自分のドキュメントを削除できなくなっていた**。`request.resource == null` のガードを追加

## クラウド同期（アカウント）について

**v4.3.0からログインが必須です。** アプリを開くとチュートリアルの後にサインイン画面（ゲート）が出て、アカウントなしでは学習画面に入れません（Firebase Authentication + Firestore、プロジェクト `wordkeep-bb145`）。単語・復習の進捗・ストリークはサーバーに自動保存され、別の端末でも同じ単語帳が開けます。

- **新規登録はメールアドレス＋6桁PIN**。PINが6桁なのはFirebaseのパスワード最小長が6文字のため。メールを必須にしたのは、PINを忘れたときの復旧手段を全員が持つようにするため
- **旧アカウント（v4.2.0以前）との互換**: 以前の登録はユーザー名を `<username>@wordkeep.invalid` という擬似アドレスに変換してメール/パスワード認証に載せていた（`.invalid` はRFC 2606の予約TLDで実在しないため、本物のメールと衝突しない）。ログインをメール必須にすると既存ユーザー全員が締め出されるため、**ログイン欄は`@`の有無でメール／ユーザー名を自動判別し、旧アカウントは今までどおりユーザー名で入れる**。新規登録のみメール必須
  - 擬似アドレスは実在しないためPIN再設定メールが届かない。旧アカウントには復旧用メールの登録を促す必要がある
- **ニックネーム（表示名）**: 登録直後の「ようこそ」画面で設定。ランキングなど他ユーザーに見える名前で、**重複可・多言語可**（絵文字も可、コードポイントで20文字まで）。ログインIDとは別物で、IDを変えずに改名できる。旧ユーザーは現在のユーザー名が初期値
  - **変更は7日に1度**。端末側の判定は開発者ツールで外せるため、`firestore.rules` の `nicknameAllowed()` でサーバー側でも検査する（`nicknameAt + 7日` を過ぎているか。値が変わらない書き込みは常に許可するので、通常の同期はクールダウンに引っかからない）
  - メールアドレスは表示名の代わりに使わない（`legacyUsername()` が`@`を含む値を弾く）。将来ランキングに出す際、メールが公開される事故を構造的に防ぐため
- **ゲートの安全弁**: `authKnown` がtrueになるまでゲートは出さない。ログイン済みなのに一瞬ゲートが出るのを防ぐと同時に、**Firebaseに到達できない端末をロックアウトしない**ため（SDKが読めなければ`authKnown`はfalseのままで、アプリはオフラインで動き続ける）
- `firebaseConfig` は秘密情報ではないので公開ファイルに直書きしています。アクセス制御はFirestoreのルール（`users/{uid}` 配下を本人のみ読み書き可）で担保
- **マージ方式**: 単語ごとに `updatedAt` を持ち、新しいほうを採用。削除は端末をまたいで伝わるようトゥームストーン（`DB.tombs`）で管理し、「削除より後の編集」は消さない。ストリークは最終学習日が新しいほうを採用しつつ `longest` は両者の最大値を保持（単純な上書きだと記録が縮むため）。ただし片側にストリーク記録が存在しない場合はフィールド単位のマージをせず、記録がある側をそのまま採用する（「記録なし」を0とみなして`min`を取ると、初回同期でフリーズ回数が消えるため）。パッケージ進捗のみ小さなブロブとして新しいほうを丸ごと採用
- SDKは数百KBあるため、**アカウント画面を開いたときか、ログイン済みセッションの復元時にだけ**CDNから遅延読み込み
- 同期の起点は5つ: 最終変更から4秒後（デバウンス）／タブを離れたとき（`visibilitychange`＋`pagehide`）／失敗時の自動リトライ（15秒→30秒→…最大5分のバックオフ）／オンライン復帰時／3分ごとの未同期スイープ。手動の「今すぐ同期」も残している
- 未同期の変更は `cloudDirty` で追跡。同期開始時にフラグを先に降ろす方式にしてあり、**同期中に加えた変更が「保存済み」と誤判定されない**（後から来た変更が取り残される競合を防ぐ）
- **端末とアカウントの結び付け**: ローカルデータの持ち主を `DB.ownerUid` で記録。ログイン時に持ち主が違えばローカルを取り込まない（前の利用者の単語が、次にログインした人のアカウントへアップロードされる事故を防ぐ）。お試し5単語は `seed:true` を持ち、既に単語のあるアカウントには混ぜない
- **ログアウトで端末を初期化**: 単語・トゥームストーン・パッケージ進捗・ストリークを消し、お試し5単語の状態へ戻す。事前に同期を試み、未送信が残る場合は警告してから実行。単語はアカウント側に残るため再ログインで復帰する
- **起動時のスプラッシュ**: ログイン状態が確定するまで表示（固定秒数ではなく、最短650ms・最長6秒）。セッション復元に通信が要るため、これが無いと一瞬ログアウト状態に見える
  - v4.1.0で導入した直後、**未ログインで開くと読み込み画面から進まなくなる重大な不具合があった（v4.1.1で修正）**。原因は`splashHidden`変数の`let`宣言より前に、それを参照する`hideSplash()`の同期呼び出し（`else hideSplash();`）が実行されてしまう順序ミス（TDZ違反）。未ログイン時は該当行が即座に同期実行されるため、宣言前アクセスで例外が発生しスクリプト全体が停止、以降の起動処理（`go('v-list')`等）が一切走らなかった。ログイン済みの復元パスは`.then()`内の非同期呼び出しだったため問題が表面化せず、検証時もログイン済みケースしか確認していなかったことが発見の遅れた原因
- 設定のバックアップ欄はログイン中「クラウドに自動保存中」と表示。かつてリスト上部に出していた「バックアップの催促」バナーは、ログイン必須化で到達不能かつ主張が矛盾するため v4.5.0 で削除した
- **復旧用メール（任意）**: アカウント画面から登録可能。Firebaseは1アカウント1メールのため、登録するとそれがログインIDになる（以後ユーザー名では入れない）。`verifyBeforeUpdateEmail`で本人確認してから切り替わる。ログイン欄は`@`の有無でユーザー名／メールを自動判別
- **PIN変更**: 現在のPINで再認証してから`updatePassword`。再認証の失敗は「現在のPINが違います」として区別（「アカウントが存在しない」と混同しない）
- **PIN再設定**: ログイン画面の「PINを忘れた場合」から`sendPasswordResetEmail`。Firebaseはアドレスの存在有無を秘匿する仕様のため、未登録でも成功を返す。文言も「登録されていれば送りました」と正直に表現している
- **復旧用メール未登録のままPINを忘れると復元手段はありません**（管理者がFirebaseコンソールのAuthentication → Users → ユーザーを編集 でPINを上書きすることは可能）

## 管理ページ（`admin.html`）について

`https://yurihmhm.github.io/wordkeep/admin.html` で、フィードバックと登録ユーザーを一覧できます。管理者アカウントでログインが必要です。

- アクセス制御は**Firestoreのルールで担保**（`firestore.rules` にUIDを直書き）。ページのHTML自体は公開されているが、管理者以外はデータを1件も読めない。ページ側の `ADMIN_UID` は表示を出し分けるだけで、防御はサーバー側
- **フィードバック**: 本文・日時・ユーザー名（未ログインなら「未ログイン」）・バージョン・言語・単語数・UA。「対応済み」フラグと削除が可能
- **ユーザー**: ニックネーム・ログインID・単語数・連続日数・最長・最終同期。**単語の中身は読めない**（ルールで`users/{uid}`の要約ドキュメントのみ許可し、`words`サブコレクションには管理者権限を与えていない）
- **アカウントの削除は2手順**: Authentication（ログイン情報）とFirestore（学習データ）は別の場所にあるため、**Authenticationでユーザーを消しても管理ページの一覧からは消えない**。完全に消すには「Authentication → Users で削除」→「管理ページで データ削除」の2つが要る。先にAuthentication側を消すこと（ログインできる状態で学習データだけ消しても、次の同期で作り直される）
  - 管理ページの「データ削除」は、要約ドキュメントの `wordIds`（単語IDの配列）を使って単語ドキュメントをIDで削除してから要約を消す。**Firestoreは削除にread権限を要求しない**ため、管理者は単語を1件も読めないまま削除だけできる。`wordIds` を持たない古いドキュメント（v4.3.0以前に最後の同期をしたもの）は、そのアカウントが二度と同期しない限りIDを知る方法がないので、Firebaseコンソールから `words` コレクションを手動削除する
- **できないこと**: PINの閲覧（ハッシュ化のため原理的に不可）、PINの再設定。これらはFirebaseコンソールの Authentication → Users から行う
- `<meta name="robots" content="noindex, nofollow">` を指定

## データについて

単語データはブラウザの localStorage にのみ保存され、サーバーには送信されません（単語検索時に辞書・翻訳APIへ単語を送る場合を除く）。端末を変えたりブラウザデータを消すと失われるため、設定タブから定期的にバックアップ（JSON書き出し）することを推奨します。

消失対策として次の2つを入れています（`wordkeep.v2`の設定に保存）:

- **永続化の要求**: `navigator.storage.persist()` でブラウザの自動削除（iOS Safariは未インストールのサイトを約7日で削除）からの除外を要求。空の初回訪問では要求せず、単語が存在するときだけ・1セッション1回だけ要求します（Chromeはエンゲージメント基準で判定するため、データがある状態のほうが通りやすい）。状態は 設定 > データ > データの保護 で確認でき、手動で再要求も可能
- **手動のJSON書き出し／読み込み**: アカウント同期があるので必須ではないが、アプリ外に自分の控えを持つ手段として残している。読み込み時はストリークを上書きせず統合し、取り込んだ単語は即座にクラウドへ送る

## アクセス解析について

Google Analytics 4（gtag.js）で匿名の利用状況（画面遷移、単語の追加・削除、復習・クイズの開始/完了と正答率など）を計測しています。`GA_MEASUREMENT_ID`（各ファイル冒頭の`G-XXXXXXXXXX`）を実際の測定IDに差し替えるまでは計測は動作しません。`localhost`/`127.0.0.1`/`file://`など開発環境では常に無効化されます。`app_name`パラメータで将来の別アプリと同一プロパティ内で横断比較できます。設定画面にも計測している旨を記載しています。

## AI機能について

以前は [Puter.js](https://puter.com) 経由でカタカナ→英単語のAI推測・例文生成を試みていましたが、Puter側の仕様で初回利用時にログインが必要になることが判明し、実用上使い物にならなかったため撤去しました。ログイン不要で使える無料AI APIが見つかれば再検討します。
